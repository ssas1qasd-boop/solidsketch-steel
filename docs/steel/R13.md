# R13: the reference model built from Tekla's IFC of the fixed model

Status: **built on branch `r13`, waiting for the owner's OK.** R12 stays the reference until then. R10, R11 and R12 are unchanged; `Frame_28x53m_R12.ss` is still rebuilt byte-identical by the same tool.

## What R13 is

`tests/steel/models/Frame_28x53m_R13.ss` is built by `tools/golden/r12_build.py R13` from Tekla's IFC export of the fixed model, `tests/steel/tekla/Frame_28x53m_tekla_v3.ifc`. This file is byte-identical to `out.ifc` in `Frame_28mx53m_Package_2.zip`. The export came from Tekla Structures 2025 SP6 as IFC2X3 Coordination View 2.0 with surface geometry, assemblies, bolts and welds switched on, the same options as R12's v2.

The owner's change in Tekla, against R12:
- the 3 mezzanine girders at C/D/E 5-6 (+4.00) had flanges and no web (R12: EB4006 top flange only, EB4008 bottom flange only);
- each now has its web FLT8*300, bolted to the column shear plates, and is one assembly;
- the model was renumbered and all drawings were made again.

### One tool, two models

R12 and R13 come from the same code. `r12_build.py` now takes the model name (`R12` is the default) and reads its inputs from the `MODELS` table:

| | R12 | R13 |
|---|---|---|
| IFC | `Frame_28x53m_tekla_v2.ifc` | `Frame_28x53m_tekla_v3.ifc` (= Package_2 `out.ifc`) |
| Document settings (grid, folders, units) | R11 | R11 (the same) |
| Part marks start from | R11 | R12 |
| Tekla's lists for the marks | Package_1 `Reports/` (Part List, Assembly Part List) | Package_2 `SingleList.xsr`, the material list on each assembly drawing, `NC/*.nc1` |
| Output | `Frame_28x53m_R12.ss`, `build/r12/` | `Frame_28x53m_R13.ss`, `build/r13/` |

`python3 tools/golden/r12_build.py R12 <file>` writes R12 to another path. After all the R13 changes, R12 rebuilt this way is byte-identical to the committed `Frame_28x53m_R12.ss`, and two R13 builds are byte-identical too.

### Parts

There are 4,948 steel, grout and grating parts, plus 176 concrete bodies. That is R12's 4,945 + the 3 webs.

- **Geometry.** As R12: Tekla's exact faceted solid with Tekla's bolt holes drilled into the part that surrounds each hole piece, stored in float32.
- **Data from the IFC.** As R12: name, profile, material, class, Tekla's weight (`st.tkW`) and length (`st.tkL`).
- **Plates and members.** As R12. Member fields are proven by rebuilding every part in the web oracle (`tools/golden/v69_build.js`): 4,361 of 4,948 parts rebuild within 0.1 mm of Tekla's solid (R12: 4,358 of 4,945; the 3 webs fit). The other 587 are the same kinds as in R12 (hooked anchor rods, skew-cut flange ends, stair treads, chamfered stiffeners). Their solids are still Tekla's exact meshes.
- **Assembly.** As R12: `st.amark` from the IFC assembly; the main part is the heaviest part, and on equal weight the one named like the assembly. In each fixed girder the top flange FLT12*250 (126.7 kg) is the main part, and the bottom flange and the web point to it.
- **Holes.** 10,024 hole pieces are drilled (R12: 9,928; + 6 shear plates × 8 + 3 webs × 16).

### Part marks

`st.pos` is not in the IFC. Tekla renumbered the whole model (for example, 4517 is now the top flange FLT12*250 and 4518 the web FLT8*300, where R12 had 4517 = web, 4518 = flange), so R12's marks cannot be kept as they are. Each part gets its mark in four steps:

1. **R12's mark.** The R13 part is paired with an R12 part as R12 was paired with R11 (same name and material, nearest box; then same profile and material).
2. **Translated through the renumbering.** Package_1's Part List and Package_2's `SingleList.xsr` are put side by side in mark order and aligned on (grade, length, weight of one part). A mark in an aligned pair becomes the new mark of that pair; any other mark is tried as it is.
3. **Checked against `SingleList.xsr`.** The translated mark is kept when the list row fits: grade, weight within 0.1 kg (the list gives 0.1 kg), and profile and length (for plates: thickness). Tekla cuts long profile names in this report (`CC200-2-2***`), so a name ending in `***` is compared as a prefix. Otherwise the part gets the fitting row that still has parts to place. Rows listed on the part's assembly drawing come first. These lists are read from the material list table of each of the 160 assembly drawings (`Assembley.PDF`, word positions from `pdftotext -bbox`), because Package_2 has no Assembly Part List report.
4. **NC holes.** Where identical list rows leave a choice, the NC files decide. The column shear plates FLT10*150 × 210 are 4506, 4514 and 4515, and differ only in their holes. The choice goes to the mark whose `NC/<mark>.nc1` has the part's holes. The part's holes are the bolt axes through it, met with its mid-plane, in its plate frame; each hole is measured to the nearer end and the nearer long edge. Each mark keeps its count.

The reason for each part's mark is in `build/r13/parts.json` (`posWhy`):

| Reason | Parts |
|---|---|
| R12 mark (translated), fits the list | 4,879 |
| Part list row (the 3 webs and 14 column shear plates) | 17 |
| Not in the list (grout, which `SingleList.xsr` does not list): R12 mark 2, 6, 8, 24, which are the same as Package_2's single drawings | 52 |

Step 4 checked all 20 column shear plates FLT10*150 × 210: 8 kept their mark and 12 were moved (6 from step 1, 6 from step 3).

The result is checked against Package_2 in `docs/steel/R13-REPORT.md`. Every mark's count and one-part weight match `SingleList.xsr`, and every one of the 1,182 assemblies holds exactly the marks and counts of its drawing's material list.

### Bolts

There are 1,700 groups: R12's 1,694 + 6. 1,294 are real bolts (TKBOLT connection + bolts body) and 406 are holes only, as in R12. The 6 new groups have 8 × M16 8.8 L45 each, and each joins a web to a column shear plate. Bolts: 4,596 (R12: 4,548).

### Welds

All 6,049 Tekla welds are in `st.tkWelds` of the secondary part (R12: 6,043). The 6 new ones are the web-to-flange shop welds.

### Checks that R13 opens and saves

- **Web.** The web oracle (v69 + the v70 chapter, as `tools/golden/lib/v69.js` runs it) opens R13 with no page errors (`tools/golden/r13_totals.js`). It reads 6,418 bodies and 1,700 connections, and its Document manager lists 160 assembly, 243 single-part and 13 GA drawings.
- **App.** The app's codec (`SsCodec`, core-io) opens R13 and saves it back byte-identical. This was checked once with a temporary JVM test, not committed (6,418 bodies). No committed app test covers R13 yet, because app sources were out of scope for this task.

The weight gap is the same as in R12: Tekla's list total is 5.9 kg above the sum of its own per-part IFC weights (R12: 5.88 kg). R13 − R12 = +311.67 kg = 3 × 103.89 kg, and Tekla's lists say +311.7.

## Against R12, by geometry

Full tables: `docs/steel/R13-REPORT.md`. Parts are paired by kind + Tekla profile + grade and a box within 0.1 mm, then compared by mesh. Bolt groups are paired by size, grade, holes-only flag and every bolt point within 0.1 mm.

- **3 new parts:** the webs FLT8*300 (mark 4518, assembly EB4007).
- **6 new bolt groups:** 8 × M16 L45 each, web ↔ column shear plate.
- **6 paired parts with another solid:** the column shear plates FLT10*150 in C2017, C2021, C2022 (×2) and C2024 (×2) are now drilled (R12: no holes). Their marks are now 4515 (3) and 4514 (3).
- **3 paired parts with another main part:** the bottom flanges FLT12*250, R12 assembly EB4008 (their own main part), are now in EB4007 with the top flange as the main part.
- **6 new welds:** web to flange.
- **Everything else is the same:** the other 5,115 paired parts have the same solid, and all 1,694 R12 bolt groups have the same bolts, grip, axis and parts joined. No R12 part or bolt group is missing.

    python3 tools/golden/r12_build.py R13
    node tools/golden/r13_totals.js
    python3 -I tools/golden/r13_compare.py
